MAHE Green Campus Dashboard (MGCD)

Single-Building Campus Implementation Cost Report

This report estimates the cost of implementing the current MGCD platform for one campus building as a real pilot project. It covers hardware, electrical integration, cloud/runtime, software enablement, annual maintenance, and rollout steps. Because an exact building was not specified, this report uses a realistic pilot-building assumption that can later be refined to your actual block.

Recommended Budget Rs 1.08 lakh to Rs 1.35 lakh

Annual Maintenance Rs 56,000 to Rs 1.08 lakh / year

1. Pilot Building Assumptions

Since the exact building was not provided, this estimate assumes a realistic first deployment for a single academic or admin block. These assumptions are intentionally practical and aligned with the current MGCD architecture.

Building type
Academic block or admin block with one main LT incomer and a few meaningful internal zones.
Size
About 5,000 to 7,000 sqm built-up area, with 500 to 900 active daily users.
Energy layout
1 main incomer + 3 internal monitoring points such as floors, HVAC branch, or lab/power branch.
Water layout
One practical water visibility layer using leak/tank monitoring first, not full campus water SCADA.
Solar layout
Either existing inverter data is available, or one extra solar feeder meter must be added.
Network model
One edge collector with LAN or 4G connection, pushing data to the MGCD backend.
Why this is the right assumption model For a first real deployment, trying to instrument every internal circuit and every pipe is not cost-effective. A pilot succeeds when it gives trustworthy building-level visibility, device health, alerts, and a credible management report.

2. What Must Be Added To The Current Project

The current software is already strong for dashboarding, forecasting, governance, audit trail, and device-readiness tracking. However, for real building use, it still needs a live telemetry bridge.

Already present
  • Dashboard UI and reporting
  • Excel import/export/reset
  • Forecasting, risk, simulator, alerts
  • Audit trail for key actions
  • Device-readiness registry
Still needed for live building deployment
  • Telemetry ingestion APIs such as /ingest/energy and /ingest/water
  • Edge collector script for RS485/Modbus polling
  • Raw telemetry storage or aggregation buffer
  • Stale-device alerting from live sync timestamps
  • Device authentication or signed ingestion keys
Cost impact
If your team builds this enablement in-house, cash cost is low. If outsourced, it should be budgeted as a one-time software integration package.

4. Final Initial Cost Scenarios

Scenario A Minimal smart pilot: Rs 70,000 to Rs 95,000
  • 3 energy meters instead of 4
  • Existing solar API, no extra solar meter
  • Water kept mostly manual or tank-level only
  • In-house software setup
This is the lowest sensible budget that still gives real building visibility.
Scenario B Recommended pilot: Rs 1.08 lakh to Rs 1.35 lakh
  • 4 energy meters
  • Device collector and protected network
  • Starter water visibility package
  • Live MGCD enablement and operator handover
This is the best balance of cost, usefulness, and management credibility.
Scenario C Advanced pilot: Rs 1.45 lakh to Rs 2.20 lakh
  • Dedicated solar meter if needed
  • Fuller water instrumentation on one main line
  • More submetering inside the building
  • Higher-quality site packaging and managed commissioning
This is suitable if the building is energy-intensive or is meant to become the showcase reference building.
Recommended answer for planning meetings If someone asks for a practical first number, use Rs 1.2 lakh per building as the planning figure for a good single-building pilot, and say that this can move down toward Rs 80k or up toward Rs 2 lakh depending on water and solar instrumentation depth.

6. Implementation Timeline

Week 1
Site survey, panel mapping, meter point confirmation, water monitoring choice, and solar data source review.
Week 2
Procurement of meters, collector hardware, UPS, adapters, and accessories.
Week 3-4
Electrical installation, CT wiring, collector setup, network connection, and basic telemetry test.
Week 5
MGCD live-enablement: device registration, ingestion script integration, dashboard mapping, and alert validation.
Week 6
User acceptance test, report review, training of building operators, and audit/device-readiness review.
Week 7-8
Stabilization window, anomaly tuning, occupancy/context validation, and management sign-off.

7. Recommended Technical Scope For The First Building

Must do
  • Main incomer meter
  • 2-3 additional internal meters
  • One edge collector
  • Protected power and network
  • Device registry and audit trail usage
Should do
  • Solar feeder integration if rooftop solar exists
  • Basic water leak or tank monitoring
  • Stale-device alerting
  • Weekly health review using audit + readiness screens
Can wait for phase 2
  • Full inline water flow metering everywhere
  • Detailed waste automation
  • LoRaWAN coverage across many buildings
  • Advanced tariff or peak-demand optimization

8. Management Recommendation

If your goal is to move from project/demo to real campus use, the strongest strategy is to make one building fully credible first.

Best budget for planning
Use Rs 1.2 lakh CAPEX and Rs 70,000 annual OPEX as the practical planning figure for one good building pilot.
Best building type to start with
Choose a building with stable occupancy, visible electrical panels, and at least one meaningful operational use case such as HVAC, labs, library, or admin operations.
What success should look like
Within 2 months, the building should show live or near-live energy visibility, device health status, alerts, sustainability reporting, and audit-backed operational changes.
